## Evidence Rules

- Evidence is source-backed, phase-scoped, and tied to the exact document, command, diff, or review result inspected.
- Report findings, DRAFT proposals, Owner constraints, source/runtime facts, and future implementation evidence are separate authority classes.
- A pending ID reserves required proof and cannot support a completed checkbox or status transition.
- This ledger proves documentation correction only. It must not repeat child production evidence or claim product behavior changed.
- Each child-correction row proves all four standard ledgers, exact slices, companion links, predecessor/successor handoff, evidence mapping, benchmark ownership, and actual-status consistency.
- P3 evidence must cover all `34` active files, not a sample or keyword-only subset.
- Completion requires independent Supervisor review of source classification, full diff, path/link matrix, content matrix, and dead-work cleanup.

### Evidence ID Naming

Use `E<phase>-<item>-<kind><n>` with exact checklist correspondence. Evidence IDs are plan-local: do not reuse an ID for a different fact inside the same standard plan set, and do not treat the same local ID in two sibling plans as one shared fact.
